Anura3D Linux / CMake Build
============================

The original Visual Studio build is still available under:

    src/VS/

The CMake build is an additional Linux build system.

Prerequisites
-------------
- Debian/Linux
- CMake >= 3.20
- Intel oneAPI Fortran (ifx)
- Intel oneMKL
- HDF5 with Fortran support
- zlib
- GiDPost

HDF5, zlib and GiDPost are external dependencies.
They are NOT built by this repository.

Load Intel oneAPI
-----------------
source /opt/intel/oneapi/setvars.sh

Configure Release build
------------------------
cmake -S . -B build \
    -DCMAKE_Fortran_COMPILER=ifx \
    -DCMAKE_BUILD_TYPE=Release

Build
-----
cmake --build build -j$(nproc)

Debug build
-----------
cmake -S . -B build-debug \
    -DCMAKE_Fortran_COMPILER=ifx \
    -DCMAKE_BUILD_TYPE=Debug

cmake --build build-debug -j$(nproc)

Non-standard dependency locations
---------------------------------
If HDF5, zlib or GiDPost are installed outside standard
system paths, provide the appropriate CMake search path:

cmake -S . -B build \
    -DCMAKE_Fortran_COMPILER=ifx \
    -DCMAKE_PREFIX_PATH=/path/to/dependencies

Visual Studio
-------------
The existing Visual Studio solution/project remains available
and has not been modified by the CMake conversion.

Success by installing oneAPI, then using the fortran compiler to compile hdf5, zlib, gidpost (at least in serial up to now) ... then a number of modifications to be sure that the hdf5 library are found/called, also adding path to hdf5 to LD_LIBRARY_PATH and LIBRARY_PATH, otherwise rather smooth.

Another rather serious issue was DSS from MKL, because now all of the old DSS symbols (dss_create, dss_define_structure, …) are  contained in the single runtime library libmkl_rt.so (the “MKL runtime” library). This helped: cmake -DCMAKE_EXE_LINKER_FLAGS="-lmkl_intel_lp64 -lmkl_sequential -lmkl_core"
